## 1. Concept

The site is a **live football broadcast of Vishal's career**: scorebug, team sheet, match timeline, highlights with "VAR reviews", a pundit studio, and full time. It is positioned as **AI/ML engineer first** (computer vision, self-retraining pipelines, generative data), product builder second (PrintSafe).

Three ideas carry it:
1. **Show, don't tell.** Every project card is playable: a demo that behaves like the real thing.
2. **Pixel-art Vishal.** The only image of him on the site is a pixel sprite. It blinks, glances, and follows the cursor.
3. **Broadcast craft.** Floodlights for the theme switch, a ticker, a whistle, crowd noise, and scroll moments in the style of Apple product pages.

## 4. Motion and sound

### Global

- Respect `prefers-reduced-motion`: turn off every animation and transition, and the kit room goes straight to "lit".
- Sound is **off by default** and toggled from the header. Every sound is synthesised in the browser with WebAudio; there are no audio files.

### Scroll moments

These use CSS scroll-driven animations inside `@supports (animation-timeline: view())`. Unsupported browsers (currently Firefox) get a normal static page.

| Moment | How it works |
|---|---|
| Progress bar | Fixed 4px accent bar, `scaleX` tied to `scroll(root)` |
| Hero exit | The text lifts away and fades (`exit 0% → 75%`) while the pitch zooms to 1.14x |
| Half-time team talk | A 240vh section with a sticky inner panel. 14 words light up one by one (word i covers `contain i·80/14%` to that value + 10%). A pixel ball rolls across underneath. |
| Career timeline | A 300vh section, pinned. The card track slides sideways with `translateX(calc(-100% + 100vw))` over `contain 5% → 95%`, and the progress bar fills in step. |
| Reveals | Section titles, cards and panels rise 70px and fade in over `entry 0% → cover 28%` |

## 6. Interactive components

The mock builds each one as a separate component so its own timer doesn't re-render the page. Keep that separation in the real build: one React component and one hook per demo.

### 6.1 PrintSafe demo

- Matches PrintSafe's real look: background `#8ec6e8` with a `#ffffff59` grid at 22px, white cards, `#0d0d0d` borders and 3px shadows, yellow `#f5c518` buttons, blue `#1a6fa8`, red `#d6384a` "Printed" stamp.
- One click runs the whole sequence:

| Stage | Time | What happens |
|---|---|---|
| 0 | idle | "Share privately. Delete automatically." Button: Encrypt & create link |
| 1 | 0–1.4s | The file's lines scramble into hex every 90ms; lock badge appears |
| 2 | 1.4–3.4s | One-time link `printsafe.in/v/3f9c2a1e#k=Zx7q…`, key part highlighted |
| 3 | 3.4–4.7s | "Shop opens it once", Printed stamp |
| 4 | 4.7–6.0s | The file splits into 7 strips that fall and tilt (shred) |
| 5 | end | "Gone. Zero trace." with a dashed "0 bytes" outline. Button: Run it again |

### 6.2 Autonomous retraining demo

- Model label `defect-yolo v14`. An accuracy chart of 24 points, ticking every 260ms.
- Accuracy drifts down by 0.002–0.006 per tick, plus noise. Bars below the dashed **0.88** threshold turn red.
- On a breach: an alert for 4 ticks, then 4 pipeline stages of 5 ticks each:
  1. Data checks: duplicates and labels
  2. Optuna tuning (trial counter climbs to 12)
  3. Retrain on a free GPU
  4. Validate and register the next version
- Then it deploys: accuracy goes back to 0.95, the version number goes up, and it serves again.
- "Inject drift" forces an immediate drop to 0.865.
- In simulation one full cycle takes about 13 seconds.

### 6.3 Image generation demo

- A 16×16 grid denoises over T = 20 steps, one every 90ms. Each cell blends from hashed noise to the target colour with weight `w = (t/T)^1.3`.
- It holds the finished image for 22 ticks, then the next one starts.
- Targets alternate between an **MLCC chip capacitor with a crack** and a **clean** one; Samsung Electro-Mechanics makes MLCCs.
- "Generate" starts the next image straight away.

### 6.4 Snake

- A 16×10 grid, ticking every 140ms. The bot plays until the visitor takes over (arrow keys, WASD, or the on-screen d-pad). There's a game-over screen and a best score.
- **Bot logic** (a stand-in for the real DQN): consider straight, left and right; drop any move that crashes; prefer moves that leave at least snake length + 2 reachable cells (flood fill); then pick the move closest to the food, with a 0.3 bias toward going straight. In simulation the bot's best score was 59.
- **Upgrade:** export the real DQN weights (an 11 → 256 → 3 network, about 4k parameters) to JSON and run Vishal's actual agent in JS.

### 6.5 Football match (Match of the day)

**Format:** 2v2 plus keepers. VA (Vishal #4 and #9) vs CPU (#3 and #5). A 90-second match where one second is one minute, with a half-time whistle at 45' and a full-time result screen.

**Controls:**
- Keyboard: arrows or WASD to move, Shift to sprint (uses stamina), X or K to pass, hold Space to charge a shot (release to shoot), tap Space to tackle while defending.
- Touch: d-pad plus Sprint, Pass and Shoot buttons.
- The player you control switches automatically to whichever of #4 and #9 has the ball or is nearer to it.

**Rules:**
- Throw-ins, corners (ball last touched by a defender), goal kicks.
- After a goal, the team that conceded kicks off.
- Every player and the ball wears a detection box with an ID, which is the link to Football Vision.

**Engine tuning** (field is 100 × 50 units, 30 ticks per second):

| Parameter | Value |
|---|---|
| Speed (walk / sprint) | 0.62 / 0.95 |
| Acceleration | 0.22 |
| Stamina | −0.011 per tick while sprinting, +0.004 otherwise |
| Ball carry distance | 2.3 (×1.3 when sprinting) |
| Pick-up radius | 2.8 |
| Fast-ball control chance | 0.3 per tick (0.85 for the intended receiver) |
| Tackle | radius 2.8, chance 0.035 per tick (×1.4 against a sprinting carrier), 55% win the ball / 45% poke it loose |
| Settle window | 14 ticks with no tackles after a change of possession |
| Shot | speed 1.8–3.3 by power; power = 0.3 + charge/24 (max 1) |
| Shot spread | `3.2·(0.35 + p²)·(0.6 + dist/40)` |
| Pass | speed 2.0 × (0.7 + dist/45), max 1.4×; aimed 10 ticks ahead of the receiver |
| Ball friction | 0.965 |
| Goal mouth | y 19.5–30.5 |
| Keeper | range y 20.5–29.5, speed 0.38 (×1.5 on a fast shot), re-reads the play every 4 ticks (a reaction delay) |
| Save | radius 2.9, one attempt per shot; chance `clamp(1.3 − 0.22·speed − 0.1·|Δy|, 0.3, 0.94)`; catches if speed < 2.3, otherwise parries |
| Keeper distribution | holds for 22 ticks, then passes to the teammate with the most space |
| Human-mode easing | CPU speed ×0.92, CPU tackle chance ×0.7 |

**AI:**
- Carrier: shoot when within 26 units of goal and under pressure, or within 15 of goal (aiming at the corner away from the keeper). Otherwise pass with 18% chance per tick when pressed and a teammate is open ahead. Otherwise dribble toward goal, sidestepping 9 units away from the nearest opponent.
- Teammate of the carrier: supporting run 15 units ahead, on the opposite side.
- Defenders: the nearer one chases the ball; the other marks the most dangerous attacker, 4 units goal-side.
- **The AI thinks in a team-relative frame** (its own team always attacks to the right). This fixed a 60/40 CPU bias that mirrored, deterministic simulations exposed. Keep it.
- Bot-vs-bot simulations average about 4–5 goals a match, with no NaN values and no stuck balls.

### 6.7 The sprite

- A 48×56 bust: curly black hair with warm highlights, thin round glasses, open brown eyes, white shirt with a blue elephant block print.
- A sheet of 5 frames: open, look-left, look-right, half-closed, closed.
- Two layers: a gaze layer (cursor-driven in the hero, otherwise a 13s glance cycle) and a lids layer for blinks.

## 9. Build plan

**Stack:** Next.js (App Router) + TypeScript, deployed on Vercel. Use CSS modules or Tailwind with the tokens above as CSS variables, plus `data-theme` on `<html>`. Keep scroll effects in CSS. Put demos in client components, one hook per engine.

**Structure:**
- `content/` holds the typed data from §5 and §7: timeline, projects, kits, Pundit Q&A, ticker. Copy edits go there, not into components.
- `lib/sound.ts` is a single WebAudio module: lazy `AudioContext`, all synths from §4, and a global mute.
- `lib/engines/` holds pure, testable functions: football `step(state, input)`, snake, retrain, gen. The UI just renders their state.

**Ask the Pundit:**
- A server route that calls Claude, with a system prompt grounded only in the §7 facts.
- Rate limiting (Upstash, which Vishal already uses for PrintSafe), a max length on questions and answers, and no data stored beyond what limiting needs.
- The API key comes from an environment variable on Vercel. Never commit `.env`.
- Choose the model and budget at build time, checking the Claude API reference for current models and pricing.

**Easter eggs:**
- Typing `VAR` anywhere turns on detection boxes across the whole page (needs a global key listener).
- The Konami code starts a penalty shootout (optional).

**Performance:**
- Pause each demo's timer when it is off screen (IntersectionObserver) or the tab is hidden (`visibilitychange`).
- Lazy-load the game.
- Preload fonts.
- Keep images small (pixel PNGs are already tiny).

**SEO and sharing:**
- Title, description, an OG image (sprite plus scorebug), a pixel-ball favicon, JSON-LD Person schema.

**Analytics:** PostHog plus Vercel Speed Insights.

**Tests** (TDD, aiming for 80%+):
- Port the sim harnesses to unit tests:
  - mirror symmetry (both teams behave identically);
  - balance (team A vs B goals within a tolerance over N seeded matches);
